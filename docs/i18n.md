# HermesChat 界面多语言（i18n）框架契约

> 本文是 i18n 层的设计与使用契约（2026-09-13 实现，D047，对应 `docs/plan.md` M6）。
> 新增/修改用户可见文案前必读本文；改 `src/i18n/` 结构时同步更新本文。

## 1. 设计概要

自研轻量实现（零新依赖，纯 TS，可被 tsc + jest + web 冒烟闭环验证）：

- **支持语言**：`zh-CN`（简体中文）、`en`（英文）。新语言只需加一个词典文件。
- **自动适配**：首帧前同步检测系统语言——原生走内置 `NativeModules.I18nManager`（Android）/ `SettingsManager`（iOS），web 走 `navigator.languages[0]`。
- **归一规则**（`resolveLocale`）：BCP47 标签精确匹配 → 主子标签匹配（`zh*` 全部归入 `zh-CN`，含 zh-TW/zh-HK）→ **兜底 `en`**。
- **手动覆盖**：`LanguageToggle` 三态循环（跟随系统 → 中文 → EN），持久化到 `hermes.locale.v1`（只存模式，不存解析结果）。
- **回退链**：当前语言词典缺键 → en 词典 → 键名本身。

## 2. 目录结构

```
src/i18n/
  index.ts            # 对外出口：t() / useT() / resolveLocale / loadLocalePreference
  localeStore.ts      # zustand：mode('auto'|Locale) + 生效 locale；持久化 hermes.locale.v1
  resolveLocale.ts    # 纯函数：BCP47 → 'zh-CN' | 'en'
  deviceLocale.ts     # 原生系统语言检测（Metro 解析）
  deviceLocale.web.ts # web 检测（vite `.web.ts` 优先解析）
  interpolate.ts      # 纯函数：'{name}' 占位符插值
  locales/
    en.ts             # ★ 键的权威来源（as const，导出 MessageKey 类型）
    zh-CN.ts          # Record<MessageKey, string>，类型强制与 en 键对齐
```

另有**独立翻译域**：`desktop/i18n.ts`（Electron 主进程，约 10 条代理错误 + macOS 菜单文案）。因 desktop tsconfig 隔离编译（rootDir 限定 desktop/）不能引用 src/i18n，自包含小词典 + `app.getLocale()` 检测，取词函数为 `dt()`。

## 3. 用法

**组件渲染路径**（订阅语言，切换即重渲染）：

```tsx
import {useT} from '../i18n';

function MyComponent() {
  const t = useT();          // 订阅生效语言 + 返回稳定的模块级 t 引用
  return <Text>{t('common.ok')}</Text>;
}
```

**非组件层**（store / rpc / ssh / utils 等抛错、拼消息处）直接调模块级 `t()`，调用时取当前语言：

```ts
import {t} from '../i18n';
throw new Error(t('chat.sendFailed', {message: e.message}));
```

**占位符**：`{name}` 形式，由 `interpolate` 替换；缺参时保留占位符便于排查。

```ts
// en.ts:  'chat.sendFailed': 'Send failed: {message}',
t('chat.sendFailed', {message: 'timeout'})  // → 'Send failed: timeout'
```

**导航标题等非 hook 取词点**：`App` 根组件已订阅语言（`useT()`），切换时整树重渲染、`options` 重新求值；自管 `setOptions` 的屏幕把 `t`（或 locale）加进 effect 依赖（先例：ProfileListScreen）。

## 3.1 语言切换入口与窗口标题

- **切换控件（LanguageToggle）挂载点**：连接主页（ConnectionHome，右上角）、原生 ProfileList header（右上）、桌面 Profile 首屏（ProfileListPane header 右上）。**会话/聊天视图不提供切换控件**（桌面 rail 底部的入口已删，避免聊天时常驻）；三态循环 = 跟随系统 → 中文 → EN。
- **桌面窗口标题**：由 `DesktopAppShell` 统一驱动（跟随当前视图：弹层标题 / 会话标题 / profile 名 / 视图名），`ProfileEditModal` 的嵌套 NavigationContainer 必须保持 `documentTitle={{enabled: false}}`——否则它会把 `document.title` 劫持在「编辑资料」上且弹层关闭后无人恢复。

## 4. 新增文案的工作流（强制）

1. 在 `src/i18n/locales/en.ts` 登记键（键名 `<域>.<名称>`，域按界面/模块：common / chat / connection / cron / session / …），同时在 `zh-CN.ts` 补中文（由 AI 助手在开发时翻译）；
2. 代码里用 `t('域.名称')` 取词，**禁止硬编码文案**；
3. 两道强制守护：
   - **tsc**：`zh-CN.ts` 类型为 `Record<MessageKey, string>`，漏键/多键直接编译失败（CI 拦截）；
   - **`node scripts/i18n-check.js`**（CI 第 4 步）：键对齐复核 + 扫描 src/ 与 desktop/ 的硬编码 CJK——**字符串字面量与 JSX 标签间文本都查**（豁免 dlog/appendLog/console 日志、`{/* */}` 注释与白名单目录）+ 未使用键报告。

## 5. 新增语言的步骤

1. 新建 `src/i18n/locales/<tag>.ts`，声明为 `Record<MessageKey, string>`（漏译处 tsc 会列出）；
2. `resolveLocale.ts` 的 `SUPPORTED_LOCALES` 加入新 tag；
3. `localeStore.ts` 的 `loadLocalePreference` 合法值集合加入该 tag；
4. `src/i18n/index.ts` 的 `dictionaries` 表注册词典；
5. 跑 `npm test`（`__tests__/i18n.test.ts` 含两表对齐断言）与 `node scripts/i18n-check.js`。

## 6. 已知限制（有意取舍）

- **已持久化的字符串不回溯翻译**：聊天时间线里的历史错误条、连接页已保存的配置名（如「浏览器直连（本机 127.0.0.1:9119）」）按写入时语言保留。
- **web 端系统语言变化不热跟随**：仅启动时检测；Android 切系统语言会重启进程，天然生效。
- **诊断日志保留中文**：dlog / appendLog / console.* 不属于用户文案，不翻译（i18n-check 豁免）。
- **dev 工具不翻译**：`scripts/`、`src/web-stubs/`（开发替身）维持中文，在 i18n-check 白名单。
- **desktop 主进程独立词典**：文案量个位数，跨 tsconfig 单源不划算（见 §2）；若后续主进程文案增多，再评估调整 desktop tsconfig rootDir 接入 src/i18n。
